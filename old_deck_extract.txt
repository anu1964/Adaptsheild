=== SLIDE 7 ===
Gaps Identified
7
Gap 1: Existing literature provides surveys and attack taxonomies but lacks functional implementations that combine detection with practical deployment in LLM applications.  |  | Gap 2: While guardian-model approaches exist, they suffer from high API costs, latency issues, and single-turn limitations, lacking multi-turn support and cost optimization. |  | Gap 3: Existing guardrails only scan user prompts, not retrieved documents/emails/PDFs |  | Gap 4: No unified risk framework that combines input-level and document-level threat scores

=== SLIDE 8 ===
Problem Statement
8
Existing LLM security tools rely on signature-based or keyword-only detection, failing against paraphrased and zero-day jailbreak prompts.  Direct Prompt Injection: Users type malicious instructions (e.g., "Ignore previous instructions…") to override system behavior. Indirect Prompt Injection: Malicious instructions are hidden inside retrieved documents (PDFs, emails, HTML) that the LLM reads, making them invisible to the user.

=== SLIDE 9 ===
Objectives
9
To build a dual-layer defense system that guards both user prompts and retrieved documents. | To design a semantic + heuristic Input Guard (Layer 1) using Sentence Transformers to detect novel jailbreak phrasing beyond keyword matching. | To develop a Document Engine (Layer 2A) that parses PDF, HTML, Email, and DOCX to extract visible, hidden, and embedded script content. | To introduce Intent Divergence Detection (Layer 2B) a novel metric comparing user prompt embeddings against document embeddings to detect semantic conflict.

=== SLIDE 10 ===
Proposed Methodology
10
Input Guard: Captures the user prompt, encodes it via all-MiniLM-L6-v2 Sentence Transformer, and computes cosine similarity against a curated dataset of 100+ jailbreak embeddings. Regex heuristics catch high-confidence patterns  | Document Engine: Parses uploaded files (PDF, HTML, EML, DOCX) using PyPDF2, BeautifulSoup4, python-docx, and custom extractors. Separates visible text, hidden, metadata, and embedded scripts. | Document Analyzer: Computes Intent Divergence - encodes the user prompt and the document's hidden/visible text separately. Measures cosine similarity; low similarity + action keywords in document = high divergence score.  | Unified Scorer: Fuses R1 (prompt risk), R2 (document risk), and Divergence into a weighted final score. Thresholds: < 0.35 = SAFE, 0.35–0.65 = WARN, > 0.65 = BLOCK.

=== SLIDE 14 ===
Module Design
14
Module 1: Input Guard - Screens user prompts for direct injection using semantic, keyword, and structural signals. | Module 2: Document Engine - Parses PDFs, emails, HTML, and Word files to extract visible and hidden text. | Module 3: Document Analyzer - Detects intent divergence between user prompts and retrieved document content. | Module 4: Unified Scorer - Fuses all risk signals into a final decision: Safe, Warn, or Block. | Module 5: Contextual Drift Detector - Maintains a rolling 5-turn buffer to catch multi-turn conversational attacks.
