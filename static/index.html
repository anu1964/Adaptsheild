Multi-Layer Input Guard

Encodes every prompt with a Sentence Transformer and computes cosine similarity against 100+ curated jailbreak patterns. Regex heuristics catch high-confidence attacks in microseconds.

Document Engine

Intent Divergence Detection

Measures the semantic gap between what the user asked and what the document actually contains. High divergence combined with action keywords triggers a document-level threat flag.

ADAPTSHIELD CAPABILITIES

Every detection signal the pipeline uses — drawn directly from the codebase.

Layer 1 · Input Guard

Semantic Jailbreak Matching

Encodes every prompt with all-MiniLM-L6-v2 and computes cosine similarity against a curated library of 100+ labeled attack examples. Similarity below SEM_LOW (0.50) contributes zero risk; at SEM_HIGH (0.80) it contributes full risk.

r1 += sem_risk
Layer 1 · Input Guard

Regex Heuristic Rules

30+ compiled IGNORECASE patterns target instruction overrides ("ignore all previous instructions"), system prompt extraction, DAN-mode, authority spoofing, and encoded payload headers. High-confidence matches alone can reach the BLOCK threshold.

heuristic_match, high_confidence_heuristic
Layer 1 · Input Guard

Attack Keyword Scoring

A multi-phrase keyword list (jailbreak terms, bypass verbs, exfiltration targets) is matched against the prompt. Each additional match increments the keyword risk contribution to R1 with diminishing returns.

keyword_match
Layer 1 · Input Guard

Technical Injection Detection

Detects Base64-encoded payloads, shell command patterns (os.system, eval()), SQL fragments, and tool-use hijacking instructions. Triggers the technical_injection_detected flag and a hard 0.75 risk floor.

technical_injection_detected, encoded_payload_detected
Layer 2A · Document Engine

Multi-Format Parsing

Native extraction from PDF (PyPDF2), HTML (BeautifulSoup4), EML (email stdlib), DOCX (python-docx), and plain TXT. Parse failures set parse_failed=True and immediately trigger BLOCK.

document_parse_failed
Layer 2A · Document Engine

Zero-Width Text Extraction

Strips and logs Unicode invisible characters (U+200B zero-width space, U+FEFF BOM, U+200C/D non-joiners) that are commonly used to hide injected instructions from human readers while keeping them machine-readable.

hidden_text field in parse result
Layer 2A · Document Engine

CSS Steganography Detection

Finds text rendered invisible via color:white; background:white, font-size:0, opacity:0, overflow:hidden, display:none and visibility:hidden in HTML and EML documents.

hidden_text / scripts fields
Layer 2A · Document Engine

Embedded Script Analysis

Extracts all <script> tag contents, eval() calls and document.write() invocations from HTML and EML sources, isolating code that could be executed or interpreted as an instruction by an agentic model.

scripts field in parse result
Layer 2B · Doc Analyzer

Intent Divergence Score

Encodes both the user prompt and the document's combined text separately with the Sentence Transformer. The cosine distance between the two embeddings is the raw Divergence signal — high distance plus action keywords equals high R2.

divergence, r2 in scores
Layer 2B · Doc Analyzer

Weighted Keyword Matching

Attack keywords found in hidden text, scripts or metadata are weighted 2× more heavily than the same keywords in visible body text, because injections live in steganographic layers — not in content the user can read.

matched_keywords in analyzer result
Layer 3 · Unified Scorer

Evidence-Gated Weighted Fusion

Final Score = R1×0.35 + R2×0.40 + Divergence×0.25. The document weights (R2, Div) are only applied when a document is attached; otherwise the scorer collapses to R1 alone. Thresholds: SAFE <0.35 · WARN 0.35–0.50 · BLOCK ≥0.50.

final_score, decision in response
Layer 3 · Unified Scorer

Output Guard

After the LLM responds, the reply is scanned for patterns indicating system-prompt leakage (e.g. the model echoing back its own instructions). A match sets decision=BLOCK, final_score ≥ 0.90 and suppresses the reply entirely.

output_guard_triggered flag

HOW ADAPTSHIELD WORKS

AdaptShield collects the user prompt and any attached document, runs them through a four-layer pipeline, and either delivers a safe LLM reply or a structured block message.

1
USER PROMPT & OPTIONAL DOCUMENT
The user submits a text prompt, optionally with an attached file (PDF, HTML, EML, DOCX or TXT). Both inputs are sent to the defense pipeline before the LLM ever sees them.
2
LAYER 1 — INPUT GUARD
The prompt is encoded with all-MiniLM-L6-v2. Cosine similarity is computed against 100+ embedded jailbreak patterns. A parallel pass runs 30+ regex heuristics for high-speed detection. Both signals are fused into R1 (0–1).
3
LAYER 2A — DOCUMENT ENGINE
If a file is attached, the Document Engine parses it and separates content into: visible_text, hidden_text (zero-width, CSS-hidden), metadata, and scripts. A parse failure immediately returns BLOCK without calling the LLM.
4
LAYER 2B — INTENT DIVERGENCE
The Document Analyzer encodes both the user's prompt and the document text independently. The cosine distance between embeddings is the raw Divergence. Attack keywords in hidden layers are weighted 2× vs. visible text, producing R2 and Divergence scores.
5
LAYER 3 — UNIFIED SCORER
Weighted fusion: Final = R1 × 0.35 + R2 × 0.40 + Divergence × 0.25. When no document is attached, the formula collapses to Final = R1, so the document weights never inflate the score on text-only prompts.
6
THRESHOLD GATE
SAFE Final < 0.35 — request forwarded to LLM.   WARN 0.35 – 0.50 — flagged but forwarded.   BLOCK ≥ 0.50 — request stopped; LLM never called.
7
OUTPUT GUARD
For SAFE and WARN decisions, the LLM reply is scanned before delivery. If the model echoes back its own system instructions, output_guard_triggered is set and the reply is suppressed — final score jumps to ≥ 0.90.
8
STRUCTURED RESPONSE
The API returns a JSON object with blocked, reply, and the full scores object (r1, r2, divergence, final_score, decision, flags, keywords). Blocked responses include blocked_by and reason.
Security and Limitations. AdaptShield's heuristic and semantic layers operate without calling an external LLM for classification. This keeps latency low but means novel, unseen jailbreak phrasings that share no semantic similarity with the training patterns may initially score below the BLOCK threshold. The thresholds (BLOCK_THRESHOLD, WARN_THRESHOLD, SEM_LOW, SEM_HIGH) are tunable constants defined at the top of input_guard.py.

01

Prompt Guard

Evaluates incoming prompts using Sentence Transformer cosine similarity against curated jailbreak embeddings, compiled regex heuristics, and keyword scoring. Operates even when no model weights are locally cached — it falls back to heuristic-only mode automatically.

02

Document Engine

Extracts all readable surface areas from a document: what the user sees, what CSS hides, what Unicode zero-width characters embed, and what embedded scripts encode. Treats a failed parse as a worst-case threat to prevent untrusted formats from bypassing inspection.

03

Unified Scorer

Enforces an evidence-gated security floor: if a document is present, its risk must be accounted for in the final score regardless of how benign the user's prompt appeared. Guarantees zero LLM tokens are consumed if Final ≥ 0.50.
